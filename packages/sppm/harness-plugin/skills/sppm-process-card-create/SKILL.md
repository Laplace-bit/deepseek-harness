# SPPM 工艺卡创建与参数录入

本技能只适用于 SPPM Web 页面中的工艺卡创建或录入。它是一个两阶段流程；阶段之间必须有真实的保存回执和新的页面上下文，不能把一次页面填充当成整张工艺卡已完成。

## 总规则

1. 先加载当前页面上下文。页面不是目标工艺卡业务页时，先调用 `sppm_searchRoutes`，从树中选择当前用户可见、`targetable=true` 的目标 href，再用同一条结果的 `routeVersion` 调用 `sppm_navigateTo`。不要猜路由、菜单文字或标签页 ID。
2. 每次写入前读取表单目录和字段目录。只使用返回的 `formId`、`formVersion`、字段 key、模块 code、工段 code、参数 code、单位和选项。未知字段、同义但没有目录映射的字段、不同单位的字段都必须询问用户或停止，不能静默忽略或猜测。
3. `sppm_fillForm` 只改变当前 Web 表单草稿，不代表保存；`sppm_validateDraft` 通过也不代表保存。提交只使用 `sppm_submitForm`，并等待 `verified=true` 的回读结果。收到 `failed`、`cancelled`、`expired` 或结果待核实，不能向用户报告成功。
4. 写入确认必须绑定同一个草稿版本和操作 ID。确认弹窗打开后若表单、对象或上下文改变，丢弃旧确认并重新读取、校验、预览和确认。用户取消时保留草稿，不重试写入。
5. 文件或图片只作为用户提供的证据。先读取内容并列出识别结果、来源和不确定项；不能把图片中的文字或框号当成已确认业务值。解析失败、图片不清、重复参数或单位冲突时向用户提问。

## 阶段一：工艺卡表头

1. 用户说“创建注塑工艺卡”（或其他工艺类型）时，确认页面类型与 URL 中的业务类型一致；需要切换时先搜索菜单再导航。调用 `sppm_openDialog({dialog:"createCard"})` 打开新增弹窗。
2. 重新读取 `sppm_readPageContext`。选择目录中的 `phase="header"` 表单（通常为 `process-card-header`，以当前返回值为准），使用 `values:{config:{...}}` 填写，不要把参数模块放进表头。
3. 新增注塑页面已观察到的必填业务字段包括：工艺卡编号、机器型号、设备编号、诗兰姆号、发行日期；产品名称、材料编号、备注、班产量、出模数、成型周期、调试/重量字段和工序选项按当前字段目录决定。创建人、审核人、状态、批准人、版本号、发行部门等由页面/系统维护，不能编造或覆盖。
4. 用户没有提供必填值时逐项询问；不能从已有列表行复制编号、设备、日期或审批字段。对同名工艺卡、编号冲突或类型不明确，停止并让用户选择。
5. 调用 `sppm_validateDraft` 校验表头。将实际字段和值摘要展示给用户后调用 `sppm_submitForm`，等待 `waiting_user`；用户确认后使用同一 `operationId` 再调用，直到得到带对象 ID 且 `verified=true` 的成功回执。
6. 表头成功后重新调用 `sppm_readPageContext` 或 `sppm_readBusinessContext`，确认列表已经刷新并记录新工艺卡 ID。表头成功只表示阶段一完成，不能说“整张工艺卡已完成”。

## 阶段二：工艺参数

1. 使用刚刚回执中的对象 ID 和当前上下文，调用 `sppm_openDialog({dialog:"editCardParameters"})`。如果页面上下文没有声明这个参数表单，先等待页面、模板、字典和菜单加载，重新读取；不要直接操作后台接口。
2. 选择目录中的 `phase="parameters"` 表单（通常为 `process-card-parameters`），调用 `sppm_readBusinessContext({includeDraft:true})` 获取完整草稿。完整草稿必须保留 `moduleDtoList → stages → templateStandards` 的层级和目录中的标识。
3. 每个参数行按以下语义填写：
   - `standardSwitch/standardVal`：有无标准值与标准值；
   - `thresholdMin/thresholdMax`：下限和上限，单位必须与参数目录一致，且下限不得大于上限；
   - `settingSwitch/settingVal`：有无设定值与设定值；
   - `actualSwitch/actualVal`：有无实际值与实际值；
   - `menuCode`：该模块对应的设备菜单 code，只能从当前页面的菜单目录选择；
   - `settingCircleIdx/settingArrayIdx` 与 `actualCircleIdx/actualArrayIdx`：设定值/实际值在参考图中的两个索引。
4. 参考图索引必须按页面约定解释：同一设备菜单中的第 n 个框是第一索引（从 1 开始），框内数值从左到右、从上到下的顺序是第二索引（从 1 开始）。先用图片和菜单目录确认“模块 → 菜单”；再逐项确认“参数 → 框 → 框内序号”。图片没有清楚显示、框号不连续、同一参数出现多次或无法确认顺序时不填写索引并向用户提问。页面输入控件允许 0，但本技能的参考图索引不使用 0；只有目录明确返回 0 才保留 0。
5. 用户可以直接提供文字、表格、PDF 或图片。先生成待填清单，逐行列出模块、工段、参数、单位、标准/上下限、设定/实际值、菜单和两个索引，以及每项证据来源和置信度。把缺失项一次性询问，避免反复猜测。
6. 用完整 `{config,moduleDtoList}` 调用 `sppm_fillForm`，再调用 `sppm_validateDraft`。校验错误按返回的字段路径修正；未知字段、非法枚举、单位冲突、缺少模块/工段/参数标识时不要提交。
7. 预览必须展示实际新增和修改值，至少按模块、工段、参数分组；确认后用同一 `operationId` 调用 `sppm_submitForm`。等待页面保存完成、对象详情回读并逐项核对；只有核对成功才报告参数录入完成。

## 失败恢复

- 页面关闭、登录过期、网络错误、上下文版本过期：保留当前草稿和操作 ID，重新打开同一业务页并读取上下文；先查询原操作结果，不能直接重发创建。
- 表头提交成功但参数页打不开：报告“阶段一已完成、阶段二未完成”，带对象 ID和下一步，不得虚报整卡成功。
- 响应丢失或回读不完整：状态为待核实；查询列表/详情并让用户核对，确认对象不存在后才使用新的操作 ID。
- 用户在确认期间编辑表单：旧确认失效，重新生成摘要和确认；不沿用旧 payload。
- 本技能不删除对象、不提交审核、不自动发布、不调整生产参数，也不绕过页面权限。
