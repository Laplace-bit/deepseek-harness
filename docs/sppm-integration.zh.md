# SPPM 集成边界

[English](sppm-integration.md) | 中文

SPPM 通过版本化的 `@deepseek-ai/dsh-sppm-ui-embed` 契约挂载 Harness React 客户端。Vue 负责浮窗和语义页面能力注册，Harness 负责会话、历史、附件、模型选择、工具结果以及 HTTP/WebSocket 流恢复。

网关验证现有 SPPM 登录，并把每个用户路由到固定的 Harness profile 和数据目录。请求方不能选择命令、profile、工作区或插件。SPPM profile 禁用终端、服务器文件、任意 JavaScript 和任意 CSS 选择器工具。

页面操作以 `@deepseek-ai/dsh-sppm-page-bridge` 的 `PageActionRequest` 跨边界传递。每条请求绑定用户会话、浏览器实例、目标页面、上下文版本、指令 ID 和有效期。Vue 拒绝过期或重复请求，并返回类型化回执。省略页面标识的工具会先通过网关解析用户当前活动页面，使模型无需命名页面即可读取或操作当前页面；多个标签页同时打开时该解析不唯一，必须显式指定浏览器实例。保存、删除和审批仍是需要真实用户确认的 Java 业务操作。

完整的上下文、请求、回执、动作、目标定位和一致性规则见 [SPPM 页面桥接协议](sppm-page-bridge-protocol.zh.md)。页面适配器发布经过白名单筛选的普通数据快照；完整业务数据和写入仍由具体动作负责。

当前实现不新增 Java 接口。业务能力通过现有 Web 客户端 API 和页面表单流程完成，桥接层只传递语义数据，并在写入后回读核对；现有 Java 服务继续执行原有权限、业务规则和事务。

模型供应商配置完全由 Harness 负责。用户通过 Harness 原生设置界面配置提供方、协议、Base URL、模型、能力和凭据；每个受管实例将这些状态持久化到自己的私有 `DSH_HOME`。网关和 Java 都不镜像、恢复或改写模型配置。Java 只负责 SPPM 身份、业务查询、草稿校验和事务写入。

## 部署与工作区

SPPM Web 嵌入模式把 Harness 进程部署在网关服务器上；浏览器只承载 React 界面和页面桥接，Java 继续负责业务规则与事务。每个用户拥有独立的 Harness 进程和 `DSH_HOME`，工作区应挂载到服务器上的专用持久目录并由服务账号控制权限。浏览器内选择器显示的是该服务器文件系统，不能访问用户电脑本地路径；桌面本地文件能力需要单独的本地 Connector。

`DSH_HOME` 保存 Harness 会话、设置和凭据，业务附件继续使用现有 MinIO。浏览器选择器负责交互，不构成多租户安全边界；生产环境必须通过容器、服务账号和文件系统权限限制可见工作区，严格根目录约束则由受限 Host 适配器提供。
